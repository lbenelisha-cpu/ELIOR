# MA100 / MA200 decision observation

This journal observes the existing live LONG strategy. It never authorizes or vetoes an order, changes an exit, or sends a broker request during a journal read. MA100/200 use closed 5-minute candles, a 10-bar slope window and both scheduled 10/20-minute checks. The displayed angle is normalized, not the screen's geometric angle.

Each record contains decision/observation time, symbol, stage, action, reason, source price/time, source clock type, version, and immutable MA snapshots. Identical evaluation states are sampled once per ten-minute bucket; changes are retained. Order attempts/intents are separate from broker-confirmed fills. Broker observations are not treated as the original strategy decision; manual requests are labelled. A WAIT/no-entry is not counted as a conflicting MA signal. Data gaps, stale snapshots and stale evaluation prices disable agreement claims.

Binance captures evaluations (including the independent exit loop), durable-order submission callbacks and confirmed fills. Its asynchronous journal writes hourly JSON shards in `/var/data/binance-ma-audit`, with atomic rename, bounded memory and a visible error/backlog. Held-asset history refresh runs separately, at most once per existing 5-minute cache bucket. The prior trading/execution journal remains authoritative. Shards older than 30 days are removed by the local writer.

Colmex attaches an optional, exception-isolated observer to the live worker. A bounded audit outbox piggybacks on existing state saves, including the pre-order reservation. After the cycle it is copied idempotently to a separate private Netlify Blobs store; only a successful save acknowledges the outbox. It is retried on the next normal cycle, never by retrying a broker order. A separate read-only 5-minute scheduled function refreshes MA context for up to three holdings. Entry scans use the history already fetched by the strategy. Missing sampler context stays unavailable. Closed-market preparation is not an automatic trading decision and is not recorded as one. Account-wide blockers before symbol evaluation remain in the existing cycle-status log.

Both private GET endpoints return up to 200 latest records from the preceding 24 hours, optionally filtered by exact symbol. Binance requires existing control/device authorization; Colmex requires existing device authorization. The public Colmex status exposes only journal health/backlog, not the new records. Colmex hourly archives remain in the persistent store; this initial UI does not provide archive export or longer range selection.

The +10/+20/+60-minute columns derive gross **price** changes from the earliest fresh recorded observation within five minutes after each due time. No historical price is fetched or invented to fill gaps; missing/late observations are explicit. Colmex quotes have receipt time, not verified exchange timestamps. These columns are not actual fills, net P&L, or evidence that changing the trading strategy would improve returns.

The new UI is collapsed by default and only reads on open/refresh. Device revocation clears loaded data and invalidates an in-flight response. Recording starts on deployment, independent of browser visibility; no historical strategy decisions are manufactured.
