# Parallel channel and paired forward observation

Binance charts now distinguish regression (blue center, purple edges) from swing-based parallel channels (orange dashed). Each can be hidden independently. The shared period control applies to both drawings; the sigma selector applies only to regression. Both use closed, contiguous candles. The parallel center is the arithmetic midpoint, not a moving average.

A swing must be strictly lower/higher than the two candles on each side; plateaus are not pivots. The latest pair at least three bars apart anchors each candidate. The opposite confirmed extreme since the first anchor sets the parallel boundary. A close outside the boundaries plus tolerance rejects the candidate. Touch tolerance is max(5% of half width, 0.01% of last close). Candidates are chosen deterministically by newest second anchor, then non-provisional status, then width. Two touches on one side and one on the other suffice for a clearly labelled provisional channel. More touches are geometric evidence, not a guarantee of reaching the other side.

The passive server study uses 100 closed 5-minute bars, regression ±2 residual RMS, and the same parallel algorithm. Every symbol is eligible no more often than every six bars. Only simultaneous valid pairs are measured. The models are frozen at observation; the endpoint is the sixth subsequent candle close (30 minutes after the baseline candle close). Collection can start up to five minutes after the baseline close; this is candle-aligned observation, not an exactly 30-minute execution return. No historical backfill or orders are performed.

Metrics: absolute endpoint-to-projected-midpoint error as percent of baseline close (lower is better), non-flat direction accuracy, endpoint containment, and full band width as percent of baseline close. Width accompanies containment to expose the advantage of broad bands. Pending samples require all six contiguous future bars, survive JSON persistence, and expire when data is missing. Availability, paired sample count, pending and expired counts are shown. Samples overlap across symbols and include provisional channels, so they are not independent statistical trials or proof of trading profitability. No automatic winner or execution change occurs.

Monitoring runs in the existing Binance LIVE observer, independently of the chart and order path. It pauses outside LIVE; missing intervals can expire. Netlify publication enables the display but cannot install the VPS observer. Owner runs scripts/install-binance-channel-monitor.sh with a full reviewed commit SHA. The installer patches only the existing observer/report/static routes, validates its anchors, backs up code and rolls back on startup failure. It does not write settings or service environment. Restart resumes existing trading settings. Verify the fresh comparison timestamp and later resolved samples in the app; startup alone does not establish successful collection.
