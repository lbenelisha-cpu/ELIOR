# Colmex Client API — read-only account connection

Credentials flow confirmed in the broker's integration message (20 October 2026), superseding the generic OAuth instructions. Live schema inspected from https://clientapi.cglms.com/traderevolution/v1/v3/api-docs . Guide: https://guide.traderevolution.com/traderevolution-api/traderevolution-apis/client-api .

Netlify Production environment variables, secret values, Functions scope only:

- `COLMEX_API_LOGIN`: TraderEvolution login supplied by Colmex (not an MT4 account).
- `COLMEX_API_PASSWORD`: account password, preserved including whitespace; never enter it in the frontend.
No extra viewing credential is required. The owner explicitly requested removal of the viewing-password requirement on 20 October 2026, after being informed that anyone reaching the page or read endpoint can view balances and positions. The endpoint is intentionally publicly readable. Broker login/password and upstream bearer tokens remain server-only; there is no trading access in this integration. Existing `COLMEX_API_READ_TOKEN` / `COLMEX_DEMO_READ_TOKEN` variables are not used by this new endpoint; the older MT4 collector may still need its own token.

After deployment open `/colmex-pro`; it automatically reads the broker account. Previously saved viewing credentials are deleted from this browser storage key. Readiness reveals configuration presence only. A single returned account is selected automatically; multiple accounts require selection. Account data is not protected by viewer authentication. Keep this distinction explicit; a public read-only endpoint does not make financial information private. There is no CORS wildcard, no tokens in URLs, no arbitrary upstream path or method.

The upstream client only permits POST `/authorize`, GET `/config`, GET `/accounts`, and GET `/accounts/{id}/state|positions`. Tokens are read from `d.access_token`, expiry in epoch seconds. Bearer is case-sensitive. Expired tokens receive at most one fresh login/retry for a read; there is no order API in this adapter. Redirects fail closed. Upstream errors are sanitized, including HTTP-200 error bodies. Wrong broker credentials have a 30-second in-process cooldown; authorization is single-flight per warm function instance. Login also resets cached config.

Account and position arrays are mapped using the current `/config` column IDs, never fixed index guesses. Schema mismatch clears the financial display and shows an error; it never means zero positions. Snapshot and account caches remain warm-instance memory only. Broker sessions are now reused across the account view, chart/quote/power functions, and scheduled/manual adapters through the server-only `levi-colmex-sessions-v1` Blobs store. Tokens are AES-256-GCM encrypted using a key derived from the existing login/password, never returned in responses or logged. Conditional writes elect one authentication request across cold starts; expired-token retries reject only the token that failed, and shared failures use a bounded cooldown. Credential rotation changes the storage key. A session-store outage fails closed rather than creating competing independent logins. Legacy Lambda handlers connect the supplied Blobs context; native scheduled functions use their existing runtime context. Default account refresh is 30 seconds, conservatively extended for known config rate-limit units, with at least 60 seconds between browser refreshes. HTTP-200 broker error envelopes are distinguished from schema errors and classified without returning provider text. The scheduled worker continues its existing cadence; no order write receives an automatic retry. `observedAt` means retrieval time, not a quote timestamp or an assurance of exchange real-time data.

Local manual tracking, external Twelve Data charts, and Wyckoff paper trading remain separate. This connection does not place/modify/cancel orders and does not automatically trade. No production credentials are used in tests. Production account verification can be performed through the read-only endpoint; a readiness success alone is not proof of broker authentication.
